## Compressed text: Payments API integration guide

Payments API clients must authenticate every request with a valid API key; requests without one are rejected. They should retry failed 503 requests with exponential backoff because 503 means the service is temporarily unavailable. They may cache successful GET responses up to 60 seconds to reduce load. They must never log a full card number, should show the API decline reason when a payment is declined, and may use the v2 or v3 endpoint, with v3 recommended.
